## 1. 设计方向

1. **简约、紧凑、工具优先**：界面只有一个职责——尽快找到文件并打开。不做文件管理器，不做信息仪表盘。【用户偏好】
2. **Windows 原生感**：采用 Windows 11 Fluent 2 的中性灰阶、4/8px 圆角、系统强调色蓝；深浅色跟随系统。【自行决定：理由 = 目标用户是 Windows 重度用户，工具应"像系统的一部分"而不是网页应用】
3. **无左侧导航栏**：参考图左侧的"搜索 / 索引状态 / 设置"导航**不采用**（用户明确不喜欢）。设置入口改为输入行右侧的齿轮按钮，索引状态并入底栏。【用户偏好】
4. **信息密度高但可扫读**：单行 32px、四列、次要文字降噪；一次呈现 10+ 行结果，匹配"扫一眼就找到"的搜索心智。【自行决定：理由 = Everything/Listary 均为高密度列表，密度是搜索工具的效率来源】
5. **双主题对等设计**：深浅两套色板同时定义、分别实测对比度，不是简单反色。【自行决定】
6. **动效克制**：只做状态反馈与窗口唤出/隐藏，无装饰动画；尊重 `prefers-reduced-motion`。【自行决定】

## 2. 设计 Tokens

**已知取舍（实现不得再扩大）**：
1. chip 未选中描边（浅 `#BFBFBF` 1.84:1 / 深 `#4D4D4D` 1.67:1）为装饰性细线；chip 的可辨识性由文字标签（AA）、选中实底填充（5.67 / 9.58）、悬停加深与聚焦环（3:1+）保证。【自行决定：理由 = Win11 控件静止描边即为此深度，加粗会破坏简约质感】
2. 高亮块与选中行底色相邻对比在浅色下偏低（`#FFD500`/`#E0EDF7` = 1.19:1），但高亮**文字**对比 11.99:1 满足正文要求，且高亮同时加粗（字重 + 颜色双通道）。深色下为 7.79:1 无此问题。
3. 行分隔线为装饰性细线（浅 1.31:1 / 深 1.18:1），仅用于弱化结构，不承载信息。

### 2.3 字体

**原则：只用系统字体栈，不引入任何字体文件/网络字体**（用户明确要求 + 启动速度 + 离线工具属性）。中文优先。【用户偏好】

#### 2.3.1 字体栈与搭配理由

| 用途 | 字体栈 | 理由 |
|---|---|---|
| 正文 / UI（sans） | `"Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei", "PingFang SC", "Noto Sans SC", system-ui, sans-serif` | ① Segoe UI 是 Windows 11 系统 UI 字体，ClearType 优化、零下载、原生感最强，拉丁文字形与 Fluent 完全一致；② 中文字形经系统逐字符回退到微软雅黑（Win11 中文版默认中文字体），保证中西文混排时不出现方框；③ 显式列出 Microsoft YaHei 兼容旧版 Windows；④ PingFang SC（macOS）/ Noto Sans SC（Linux）作为跨平台回退，虽然非目标平台但成本为零。**只用一款字体的不同字重表达层级**，无第二套展示字体——搜索工具需要"无个性的界面"，字体个性越弱，文件名内容越突出。【自行决定 + 用户偏好】 |
| 数字 / 日期（mono） | `"Cascadia Mono", "Cascadia Code", Consolas, "Courier New", monospace` | 用于大小、修改时间两列：① 等宽字形保证数字列右对齐稳定，**滚动时数值变化不会引起列宽抖动**（虚拟滚动下尤其重要）；② Cascadia Mono 为 Win11 自带，Consolas 兼容旧版；③ 日期列用等宽可让 `10-15` 与 `2024-10-15` 混排时冒号/连字符对齐。路径列仍用 sans（路径含中文与反斜杠，等宽收益低且更占视觉重量）。【自行决定：理由 = number-tabular 原则 + 虚拟滚动稳定性】 |

#### 2.3.2 字号阶梯

紧凑密度，最小 12px（不出现 11px 以下文字）。【自行决定：理由 = 桌面工具、高密度列表；13px 是资源管理器/Everything 的行文字舒适区】

| Token | 字号 | 用途 |
|---|---|---|
| `fs-lg` | 20px / 600 | 设置页标题 |
| `fs-md` | 16px / 600 | 设置页分组标题、空状态主文案 |
| `fs-input` | 14px / 400 | 搜索输入框 |
| `fs-name` | 13px / 400 | 结果行文件名（主信息） |
| `fs-meta` | 12px / 400 | 路径、大小、日期、列头、chips、底栏 |
| `fs-tertiary` | 12px / 400 | placeholder、空状态辅助文案、禁用 |

字重只用三档：`400`（正文）/ `500`（列头、chip 选中态文字、选中行文件名）/ `600`（标题：设置页标题与分组标题、空状态主文案、匹配高亮文字）。

行高：列表行固定 `32px`（虚拟滚动要求行高确定）；输入框 `1.4`；设置页正文 `1.5`。

### 2.4 间距 / 圆角 / 边框 / 阴影

**间距刻度**（4px 基数）：`2 / 4 / 8 / 12 / 16 / 24`。
- 输入行：总高 44px（垂直内边距 4px + 输入框 36px）、水平内边距 12px；
- 输入框与 chips 行间距 8px；
- chip 高 24px、内边距 `4 10px`、chip 间距 8px；
- 列头高 24px、左右内边距 12px；
- 结果行水平内边距 12px；图标 16px，图标与文件名间距 8px；
- 底栏高 28px、水平内边距 12px；
- 设置页分组间距 24px、组内控件间距 12px。

**圆角**：窗口 `8px`（Win11 窗口圆角）；输入框 / chip / 按钮 `4px`；托盘菜单与下拉 `8px`。【自行决定：对齐 Fluent 控件规格】

**边框**：一律 1px `border-subtle` 细线（行分隔、列头下线、chips 行下线）；聚焦环 2px `border-focus` + 2px 偏移（双主题均 ≥3:1，见 §2.2）。【自行决定】

**阴影**（仅浮层，列表/卡片零阴影，保持扁平）：
- 窗口（贴桌面悬浮）：浅 `0 16px 40px rgba(0,0,0,.18)` / 深 `0 16px 48px rgba(0,0,0,.55)`，外加 1px `window-border`；
- 托盘菜单 / 下拉 / 气泡：浅 `0 8px 20px rgba(0,0,0,.14)` / 深 `0 8px 24px rgba(0,0,0,.50)`，外加 1px `border-subtle`。
【自行决定：理由 = 启动器窗口悬浮于其他窗口之上，需要与桌面内容分层；列表内不使用阴影，避免视觉噪音】

### 2.5 结果行高与信息密度

| 项 | 值 | 说明 |
|---|---|---|
| 行高 | **32px** 固定 | 图标 16px 垂直居中；默认 760px 宽窗口一屏 11 行 |
| 文件名 | 13px `text-primary` | 过长省略号截断 + tooltip 显示全名 |
| 次要文字（路径/大小/日期） | 12px `text-secondary` | 降噪但保持 AA（7.00 / 8.75） |
| 列：名称 | `minmax(140px, 1fr)` | 图标 + 高亮文件名 |
| 列：路径 | `minmax(110px, 1fr)` | 右对齐？否——左对齐省略号；路径为次要信息 |
| 列：大小 | 68px 右对齐 | mono 栈；目录显示空白 |

## 6. 可访问性与交互约定

1. **焦点样式清晰可见**：所有可交互元素聚焦时 2px `border-focus` 环 + 2px 偏移（对比度见 §2.2 非文字表）；结果行键盘焦点 = 选中行本身的选中样式 + 环；Tab 顺序与视觉顺序一致。【自行决定】
2. **对比度**：正文与背景 ≥4.5:1，关键组合实测值见 §2.2（全部通过）；实现后任何色值变更必须重算并保持达标。【自行决定：任务要求实测并写入】
3. **不只靠颜色表达状态**：选中行 = 底色 + 左侧 3px 指示条；排序 = `▲/▼` 字符 + 列头按钮 `aria-pressed`（`aria-sort` 只合法于 `columnheader`/`rowheader`，本列表非 `role="table"`，故不使用，见 §3.6）；错误 = 图标 + 文字；扫描中 = 进度百分比文字；高亮 = 黄底 + 加粗；chip 选中 = 实底填充 vs 描边（形状差异）。【自行决定：a11y】
4. **深浅色跟随系统**：`prefers-color-scheme`；同时设置 `color-scheme: light dark` 使滚动条/表单控件跟随。不提供手动覆盖（从简）。【DESIGN §11.1 + 自行决定】
5. **虚拟滚动约定**：使用 `@tanstack/react-virtual`（DESIGN §2.1）。一次只渲染可见窗口；取数范围为**可见窗口 ±1 屏**（DESIGN §11.1）；行高固定 32px；滚动停止后才发 `range` 请求（滚动中以旧数据渲染），快速滚动时丢弃未返回的窗口请求；`offset` 越界返回空数组由 UI 优雅处理。【DESIGN §11.1 + 自行决定：滚动节流策略】
6. **语义与播报**：列表 `role="listbox"`、行 `role="option"` + `aria-selected`；加载中列表 `aria-busy`；底栏命中数 `aria-live="polite"` 完整短语播报；图标按钮（⚙/✕）有 `aria-label`（"设置"/"清空"）；装饰性图标 `aria-hidden`。【自行决定：a11y】
7. **尊重系统设置**：`prefers-reduced-motion`（§2.6）；系统文字缩放（Win11 显示缩放 ≥125% 时布局不截断——列表列 flex 收缩，最小窗口 640px 保证）。【自行决定】

## 7. MockEngine 约定（规格层面）

UI 通过 `EngineClient` trait 的同形接口取数（DESIGN §2.2-1、§9）。**架构原则：接口同形、实现可换**——浏览器原型用 TS Mock，M3 换 Tauri invoke，M6 换 Pipe；**UI 代码不分支、不感知背后实现**。以下为规格约定，不含实现代码。

### 7.1 接口映射（接口同形、实现可换）

UI 代码只依赖一个与 `EngineClient` trait **同形的 TypeScript 接口**（`search` / `range` / `cancel` / `status` 四个方法，参数与返回结构照 DESIGN §9 类型原样翻译为 TS）；背后实现按阶段整体替换，UI 代码不改动、不做任何分支：

| 阶段 | 底层实现 | 传输方式 |
|---|---|---|
| **原型阶段（本轮）** | **MockEngine = TypeScript 实现**：前端内存生成数据、前端模拟延迟与取消 | 进程内 Promise，无 IPC |
| **M3（Tauri 外壳）** | Rust 侧 `InProcess` 实现的 `EngineClient` | 同一 TS 接口的底层切换为 `invoke` → Tauri command |
| **M6（服务拆分）** | Rust 侧 `Pipe` 实现的 `EngineClient` | 同一 TS 接口的底层切换为命名管道客户端（DESIGN §10.1） |

UI 依赖的四个方法（TS 同名同结构）：

| 接口方法 | 返回 |
|---|---|
| `search(req: SearchRequest)` | `SearchSummary { id, total, elapsed_ms, parse_error }` |

- **`ParseError` 必须与 Rust 侧逐字段对应**（M19）：

  | Rust `ff_core::ParseError` | TS `ParseError` | 说明 |
  |---|---|---|
  | `message: String` | `message: string` | 引擎给出的具体原因，UI 必须原样展示（§4.6） |
  | `span: Range<usize>` | `span: { start: number; end: number }` | 半开区间 `[start, end)`；TS 没有 `Range`，逐字段展开为对象，不做类型擦除 |

  `Range<usize>` 在 TS 侧没有等价类型，若图省事把 `span` 擦成 `number` 或整个 `ParseError` 擦成 `string`，M3 接线时 `invoke` 的 JSON 反序列化会直接在两侧同时报错，且错误点分散在 UI 各处难以定位——故契约必须在原型阶段就写全。【M19】
| `range(id: RequestId, offset: number, limit: number)` | `ResultRow[]` |
| `cancel(id: RequestId)` | `void` |
| `status()` | `EngineStatus`（各卷 Scanning(进度)/Ready/Error、条目数、最后保存时间） |

- **本轮硬性要求**：原型必须能在普通浏览器里 `vite dev` 运行（方便截图对比参考图）。浏览器里没有 Tauri 的 `invoke`，因此本轮的 MockEngine **只能是 TS 实现**，应用代码只依赖上面的 TS 接口。【用户工作流硬性要求】
- Rust 侧 MockEngine（`EngineClient` 的测试替身，与 `InProcess` 并列）**降级为可选**：仅供引擎/QA 的 Rust 单测使用，不是前端原型的依赖。【自行决定】

### 7.2 MockEngine 行为规格

| 项 | 约定 |
|---|---|
| 运行环境 | **纯浏览器**（`vite dev`），不依赖 Tauri；所有行为发生在前端内存中。【用户工作流硬性要求】 |
| 数据规模 | 启动时在前端内存生成 **300,000 条**合成条目（固定随机种子、可复现）：中英文混合文件名（含可被拼音首字母命中的中文名）、4 层目录树、目录:文件 ≈ 1:6、大小对数分布 0B–4GB、mtime 近 8 年。【自行决定：覆盖 §1.3 的 200 万目标的约 1/7，足以验证虚拟滚动与交互；真实数据压力由引擎 Track 负责】 |
| `search` 延迟 | 前端用 `setTimeout`/Promise 模拟 20–60ms（模拟 Top-K 计算）；返回 `total` 与 `elapsed_ms`；取消用**前端标志位模拟协作式取消**——延迟等待中检查标志，置位即放弃该次回包。【DESIGN §2.2-6 + 自行决定】 |
| `range` 延迟 | 前端 `setTimeout` 模拟 5–15ms / 窗口；返回行含 `name_matches`（对查询词在名字中的实际位置做子串高亮计算）。【DESIGN §9 + 自行决定】 |
| `cancel` | 幂等、立即生效（清除标志位）；被取消 id 的后续 `range` 回包由 UI 按 id 丢弃。【DESIGN §9 + 自行决定】 |
| `status` | 初始模拟一次 3 秒扫描进度（Scanning 0→100%）后转 Ready；之后每秒可轮询；Ready 态返回 `索引就绪 · 300,000 条 · 已保存 <时间>`。【自行决定：验证扫描态 UI】 |
| 取消语义 | `search` 自动取消同一客户端上一次未完成搜索（DESIGN §9）；UI 侧只渲染最新 id。【DESIGN §11.1】 |

### 7.3 UI 对接口的期望

1. `search` 尽快返回 `total`（首屏渲染只依赖 summary）；高亮等昂贵信息只在 `range` 为窗口内行生成（DESIGN §9）。
2. 同一 id 的 `range` **分页稳定**：重复请求同一窗口返回一致数据，滚动往返时行不错位。
3. `offset` 越界返回空数组而非错误。
4. 旧 id 的一切回包一律丢弃（请求 id 机制，DESIGN §11.1 验收项）。
5. `status` 轮询 1s 一次即可（M3 不做订阅推送）。

### 7.4 UI 状态机（加载中 / 取消 / 无结果）

```
                 ┌────────── 按键 ┌─────────┐
                 ▼               │         │
[idle 空查询提示] ──按键──▶ [requested] ──summary 到达──▶ [rows streaming] ──窗口取完──▶ [done]
   ▲                        │  ▲                          │
   │                        │  └── 再按键: cancel(旧id) ──┘（保留旧列表渲染，不清空）
   │                        └── ≥250ms 无 summary: 输入框 spinner + 列表 aria-busy
   └── Esc / ✕: cancel + 清空输入
```

| 状态 | 列表区 | 输入行 | 底栏 |
|---|---|---|---|
| idle（空查询） | 空查询提示（§4.4） | 默认 | 索引状态 |
| requested | 保留旧结果；≥300ms 且为空 → 骨架行 3 行 | spinner（≥250ms） | `搜索中…` |
| rows streaming | 顶部 2px 不确定进度条 + 渲染已到行 | spinner | `搜索中…` |
| done | 正常结果 | 无 spinner | `找到 N 个结果 · T ms` |
| done（total=0） | 无结果空状态（含"清除筛选"动作） | 无 spinner | `找到 0 个结果 · T ms` |
| parse_error | 保留上次有效结果 | 错误条 | 上次命中数 |
| cancelled（被新按键取消） | 旧结果继续渲染至新 summary 到达 | 新 spinner | `搜索中…` |
| 引擎 Error | 错误态 + 重试按钮（§4.6） | 可用 | 错误文案 |

- **无结果**不是错误：不得弹窗、不得清空输入；提供"清除筛选 / 缩短关键词"两个可执行建议。【自行决定：理由 = 搜索工具的常见挫败点】

## 10. 待用户决定（附推荐）
